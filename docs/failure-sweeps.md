# Failure sweeps: pre-flight guards against classes already hit

Every failure class below was hit at least once against the real GPU box or
a live browser, at a cost of a ~10-minute box boot (or worse) per incident.
Each row is: what happened -> what the codebase-wide sweep found -> the
permanent guard now in place (a test, unless noted).

Follow-up review found the original guard only checked call ARITY (`inspect.signature`), which is blind to `enc.encode(clip.frames)` vs `enc.encode(clip)` -- both are exactly one positional argument. ## Smoke tier (split: `smoke` <=10s torch-free + `smoke_torch` unbounded)

Profiling found `import torch` alone costs ~15s cold in this environment
(confirmed by timing `uv run python -c "import torch"` standalone) -- not
anything in the smoke tests' own logic, which runs in well under 1s
combined once the interpreter is up. That makes any single tier that needs
torch structurally incompatible with a <=10s budget here, so the tier was
split in two:

- `tests/test_smoke.py` (`pytest -m smoke`) -- TORCH-FREE. Imports every
  torch-free `physics_auditor.*`/`scripts/*.py` module (a `TORCH_MODULES`
  set excludes the rest and is itself pinned against drift), runs one
  reduced-config minimal-pair generation, runs VoE against a deterministic
  stub adapter, renders a report card, exercises the monitor's threshold
  math on synthetic scores, and calls the gallery data builder's pure
  functions on synthetic input. **Measured: `uv run pytest -m smoke -q
  tests/test_smoke.py` runs in ~2s pytest-internal / ~5s wall including `uv`
  + interpreter startup -- within the <=10s hard rule.**
- `tests/test_smoke_torch.py` (`pytest -m smoke_torch`) -- the torch-backed
  counterpart: imports `physics_auditor.models.{encoders,predictor,
  pretrained,stacks}` and the torch-using `scripts/*.py`, constructs +
  mock-encodes every encoder class, checks predictor rollout shape. Not
  held to a time budget (pays the one-time torch import cost, ~16s
  measured), but still mock-injected only -- no network/`.load()` calls.

Both markers are registered in `pyproject.toml`. `scripts/aws/remote_job.sh`
runs `-m smoke` then `-m smoke_torch` back to back before the full `pytest
-q`. `scripts/fresh_clone_smoke.py` (the pre-GPU-launch gate) runs `-m
smoke` only, and now measures its own wall time and fails if it exceeds the
10s budget in the fresh-clone export, not just checking the exit code.
